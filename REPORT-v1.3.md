## Normative rulings and retained checks

The [versioned v1.3 projection](kogen_conformance/v13.py) applies after row/template expansion only when the v1.3 overlay is selected. Historical profile selections retain their schema and fixture contracts. The four direct public-fixture corrections fix encoded neutral-name substitutions and restore genuinely distinct conflict values.

- **Shared schemas, scoped calls:** §4.9.2 and §4.2 require all seven canonical definitions (`edit`, `finish`, `read`, `search`, `shell`, `tool_output`, `write`) in both injected and Owned codecs. §4.7 still limits which functions a role can call. Every projected schema script checks the complete inventory and exact `allowed_tools` set or `none`. Explicit request assertions retain headers, forbidden fields, strict finish schema and three-tool shell permissions. The reusable-prefix oracle now also requires `edit`, exact inventory cardinality, schemas and static generic content.
- **Fresh requests and reusable prefixes:** §4.9.2 requires generic/role developer content before task history, so the literal single-input fake decoder from §4.8.2 cannot describe the new prefix. Exclude developer/system/schema items only to recognize the first user history. Later turns compare every previous input item, including that prefix. Provider-visible role markers are asserted across system/developer instructions; Shape's original anchored task pattern is asserted against its first user message. Retry bodies, thread identities, history, static prefix and all outcome checks remain asserted. Outer JSON serialization is not substituted for provider-visible prefix equality.
- **Exact-base approval:** §3.3 and §2.9 permit disposable scratch checks of the resolved base. PID/counter markers and the readable setup-success marker live outside scratch; setup failure counts come from retained logs, so the fake need not write outside confinement. The required dead processes, exactly-once baseline, two failed setup attempts and queued/stopped outcome remain checked. Recovery fixtures observe the exact §5.4 workspace path from the harness instead of asking a confined child to write an external marker; missing workspaces fail immediately, and exact snapshot/publication/live-owner checks remain unchanged. The Build-confinement attack is armed after approval, so it attacks the intended operation.
- **Fixtures and event matching:** CRLF and invalid UTF-8 remain exact-byte assertions. The two moving-base fixtures again create a real conflict and additionally require `rebase_conflict` repair. Event-name strings mean an event object's `event` field (§2.8); missing events fail. A long synchronous reapproval fake sends legal SSE comment bytes (§4.5) while its side effect runs; first-byte, idle and total deadline checks remain active. ExUnit completion fakes use the already-required finish-alone object (§3.6). The leading `~` is matcher syntax, not CLI output: §1.7.4 requires plain `landed`. Rust's literal tilde and the inherited escaped-marker expectations are both corrected; the exact line remains mandatory. Coverage fakes account for both quoted request constraints (§3.2.3).
- **Rust corrections:** §2.4.3–4 requires adapter-aware named ExUnit findings in approval baselines. Approval and gate checks now share full-log parsing; cached parser identity is versioned, and a different test cannot be excused by an old failure. §2.3/§2.4.3/§3.2.3 requires the adapter-default Shape formatter, including the hidden generated acceptance source. §2.8 requires the candidate ledger at the run root; Rust now publishes a private, initially empty report there and grants that file through confinement, without granting sibling run-state writes. Precreation also makes the file available for Linux bind mounts. §1.7.4 requires plain landed output: the CLI no longer emits the copied literal matcher tilde. The suite keeps exact ledger rows, formatted bytes and landing lines.
